# АВТОФАКУЛЬТЕТ · первое обращение

Персональная демонстрация для авто и мотошколы в Нижнем Новгороде. Помогает до поступления: пожелания → программы для обсуждения → заявка → уточнение → предложение сотрудника → ответ ученика.

**Демо:** https://artemdiscipline.github.io/avtofakultet-demo/  
**Репозиторий:** https://github.com/Artemdiscipline/avtofakultet-demo

В браузерном режиме нет регистрации, токенов и внешней отправки. Черновик и обращения сохраняются в localStorage текущего браузера. Переключатель ролей — часть демонстрации. В другом браузере или на другом устройстве локальных заявок не будет. Не используйте реальные контакты для показа.

## Быстрый запуск

Нужен Node.js 22.13+ (рекомендуется 24 LTS). SQLite используется через встроенный `node:sqlite`; сообщение об экспериментальном API допустимо для этой демонстрации.

```powershell
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173/avtofakultet-demo/. Файл .env для браузерного демо не нужен.

```powershell
npm test
npm run build
npm run preview
```

Проверки включают ветвление, восстановление навыков, неизвестные данные, контакты, сбой записи, идемпотентность, снимки, подпись Telegram, права владельца и администратора, конфликт версий. Протокол UI-проверок — [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Показ за 2–3 минуты

1. Откройте демо на телефоне в роли «Ученик». Выберите B → с нуля → автомат → будни, вечер → ближайшее время.
2. Отметьте «Оплата частями». Посмотрите «Стандарт» АКПП и сравнение с «Микс». Выберите интересующую программу.
3. В проверке заявки нажмите «Изменить» возле графика; добавьте выходные и вернитесь. Нажмите «Заполнить тестовыми данными» и «Создать тестовую заявку».
4. Нажмите «Посмотреть глазами администратора». Покажите тот же номер и все ответы. Выберите «Нужно уточнение», спросите: «Подойдёт ли практика по выходным?»
5. Переключитесь в «Ученик», ответьте. Вернитесь в «Администратор» → откройте заявку → «Предложить программу» → «Стандарт» АКПП → комментарий и сохранение.
6. В роли ученика нажмите «Хочу обсудить эту программу». Обновите страницу: статус, предложение и переписка сохранены.

Это обращение для подбора, а не зачисление, оплата или бронирование занятия.

## Структура

- `src/catalog.ts` — подтверждённые программы и FAQ с источником и датой.
- `src/model.ts` — общая модель, схемы валидации, правила подбора и переходов статуса.
- `src/Wizard.tsx`, `src/RequestDetail.tsx` — анкета и работа с обращением.
- `src/storage.ts` — интерфейс хранилища, браузерный и HTTP-адаптеры.
- `server/db.ts` — SQLite, серверное владение, идемпотентность, транзакции, версии, outbox.
- `server/auth.ts`, `server/app.ts` — HMAC initData и API с проверкой доступа.
- `server/bot.ts`, `server/telegram.ts` — отдельный бот, /start и Mini App, тестовые уведомления.
- `docs/SOURCES.json` — сведения по каждой программе и ответу FAQ.
- `docs/SOURCES.md` — расхождения источников, изображения и ограничения данных.

Обе реализации используют `Application`: `id`, `createdAt`, `updatedAt`, `status`, `applicant`, `category`, `experience`, `transmission`, `schedulePreferences`, `desiredStart`, `questions`, `interestedPrograms`, `programSnapshots`, `adminReply`, `messages`. Дополнительно — `helpFocus`, `situation`, `idempotencyKey`, `version`.

При отправке снимки копируются из каталога. Сервер самостоятельно формирует цену и снимок. Отправленная заявка не обновляется при изменении каталога. У предложения сотрудника свой снимок. Идемпотентность создания на сервере ограничена владельцем; обновления требуют текущую версию. Браузерные вкладки используют Web Locks, где они доступны, и проверку версии.

## Подключённый Telegram-режим

**Подготовлен к настройке, фактически не подключён и не проверен на реальном Telegram.** Существующий `hi_prof_bot` и учебная платформа школы не использовались. При старте сервера и бота выполняется read-only `getMe`: имя должно совпасть с `TEST_BOT_USERNAME` и не быть `hi_prof_bot`.

1. Создайте **отдельного тестового бота** через BotFather. Получите его токен; настройте HTTPS-домен Mini App для этого бота.
2. Скопируйте `.env.example` в `.env`. Заполните `BOT_TOKEN`, `TEST_BOT_USERNAME`, `MINI_APP_URL`, `ADMIN_TELEGRAM_IDS`, `TEST_ADMIN_CHAT_ID`. Укажите числовые ID тестовых сотрудников. Администратор уведомлений должен сначала открыть именно тестового бота командой `/start`.
3. Разместите API на Node.js-сервере с **постоянным диском**. `DATABASE_PATH` должен указывать на постоянный том. Настройте резервное копирование SQLite, HTTPS reverse proxy к `127.0.0.1:3001`, процесс-менеджер, отдельный системный аккаунт. API не публикует содержимое базы как статические файлы.
4. Запустите отдельными процессами:

```powershell
npm run server
npm run bot
```

5. Соберите отдельный frontend с `VITE_STORAGE_MODE=server`, `VITE_API_URL=https://your-api.example`, нужным `VITE_BASE_PATH`. В `ALLOWED_ORIGINS` укажите origin frontend (без пути). Эти VITE-переменные публичны; секретов в них быть не должно. Не меняйте режим публичного браузерного демо для первого показа.
6. Откройте `/start` в тестовом боте и нажмите «Подобрать обучение». Используется официальный Telegram Web App SDK. Raw `initData` передаётся API в Authorization; `initDataUnsafe` не используется. HMAC проверяется по официальному [механизму Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), срок — 1 час, допустимое опережение часов — 30 секунд. При истечении нужно переоткрыть Mini App.
7. Проверьте двумя Telegram-аккаунтами: ученик видит только свои обращения; сотрудник из серверного списка — обращения проекта. Переключателя деморолей здесь нет. Неавторизованный браузер получает закрытый экран. Telegram ID и канал через бота берутся из проверенных сервером данных; телефон необязателен.
8. Проверьте получение уведомления только `TEST_ADMIN_CHAT_ID`, затем уточнение, ответ ученика и предложение с другого устройства. Обновление данных — при возврате в приложение, кнопкой обновления и каждые 15 секунд. Websocket не требуется.

Уведомления о новых заявках идут только отдельному тестовому администратору; других автоматических исходящих рассылок нет. Outbox переживает перезапуск, повторяет неудачные попытки с увеличением интервала. Доставка Telegram — at-least-once: при сетевой неопределённости одно уведомление может повториться; номер заявки позволяет распознать повтор. Создание заявки от уведомления не зависит. Ответ ученику виден внутри Mini App после обращения к API.

Перед рабочим использованием со школой отдельно согласуйте хранение и обработку персональных данных, организационные права, актуальный каталог, договор и контакты. Физический телефон, реальный токен, межустройственная синхронизация и доставка Telegram пока не проверены.

## Публикация браузерного демо

GitHub Actions запускает тесты и сборку, затем загружает только `dist/` в GitHub Pages. Репозиторий содержит исходники обоих режимов, но **backend и бот на Pages не запускаются**. База, `.env`, контакты, введённые в браузере, и `node_modules` игнорируются Git. Hash routing обеспечивает прямое открытие и обновление внутренних экранов в `/avtofakultet-demo/`. Шрифты и фотография размещены локально в сборке; CDN для демо не нужен.

Для другого пути измените `VITE_BASE_PATH` и конфигурацию Pages. При изменении каталога снова проверьте официальные страницы, обновите дату и файл источников. Данные на 23.10.2026 — ориентиры для обсуждения, не бессрочное предложение школы.

## Ограничения демонстрации

Здесь нет платежей, договора, записи на время, учебного кабинета и выдачи доступа к образовательной платформе. Никаких выдуманных заявок. Смена роли в браузере не обеспечивает безопасность и не предназначена для реальной работы школы. Очистка браузерного хранилища удаляет локальные записи. При запрете хранилища успех создания не показывается; ответы остаются в памяти страницы для повторной попытки.
